# Asset Specification & Technical Contract

This contract defines concrete technical defaults compatible with **Godot 4.7 (`res://`)** and [`tools/gameforge-kit/`](../../tools/gameforge-kit/AGENTS.md).

## 1. Folder & Naming Conventions

- **Root Structure:**
  - `assets/source/<domain>/`: Raw artist/AI working files (unpacked frames, PSD/layered exports, unnormalized renders).
  - `assets/base/<domain>/`: Approved/normalized static tiles, props, or un-packed clean base frames ready for packing.
  - `assets/generated/`: Toolkit-packed atlases, `.atlas.json`, and Godot `SpriteFrames` `.tres` (written only by `gameforge-kit` or verified pipeline scripts).
  - `assets/previews/`: Contact sheets, GIFs, and HTML gallery previews.
- **Naming Rules:**
  - Lowercase `snake_case` ASCII only (`[a-z0-9_]+`). No spaces, uppercase, or Vietnamese diacritics in filenames.
  - Animated sprite tasks follow `gameforge-kit` profile naming: `{character}_{animation}_{direction}` (e.g., `player_hero_idle_down.png`).
  - Raw source frames inside a task folder: `frame_000.png`, `frame_001.png`, ... (zero-padded 3 digits).
  - Static environment/prop PNGs: `<category>_<asset_name>_<variant>.png` (e.g., `ground_jade_tile_01.png`, `prop_lantern_01.png`).

## 2. Image Format & Transparency

- **Format:** `PNG` with `RGBA` 8-bit/channel (`png_rgba`).
- **Background:** 100% transparent (`alpha = 0`) outside the asset silhouette. No checkerboard, solid white, or baked sky backgrounds.
- **Texture Filter:** `nearest` (configured in `profiles/cloudbound_isometric.json` and `project.godot` `default_texture_filter=0`) or crisp hand-painted `linear` only if explicitly overridden per resource. Keep edges clean without haloing/premultiplied-alpha artifacts.

## 3. Tile & Environment Prop Dimensions

- **Modular Ground Tiles:** `128x128` px (or `128x64` px for 2:1 isometric diamond tiles; `128x128` square top-down/3-4 tiles recommended for `TileMapLayer`).
  - **Seamless Edges:** Ground/cloud-floor tiles must tile seamlessly on all 4 edges (or 4 isometric edges) with no visible seam lines.
- **Platform Edges / Bridges:** `128x128` px or `256x128` px modular segments with consistent `32–48px` vertical front thickness for 2.5D depth.
- **Environment Props:** `64x64`, `128x128`, or `128x192` px (pillars/gates), bottom-center aligned so collision bases match `Y-sorting`.

## 4. Character, Enemy, Boss & VFX Sprite Frames

Compatible with `profiles/cloudbound_isometric.json`:

| Entity Class | Frame Size | Safe Margin | Pivot (`bottom_center_feet`) | Godot Scale |
| --- | --- | --- | --- | --- |
| Hero (`player_hero`) | `128x128` | `4px` | `(64, 112)` → `offset = (0, -48)` | `1.0` |
| Standard Enemies (`melee`, `ranged`) | `128x128` | `4px` | `(64, 112)` → `offset = (0, -48)` | `0.9` |
| Heavy Enemy (`tank`) | `128x128` | `4px` | `(64, 112)` → `offset = (0, -48)` | `1.15` |
| Boss (`boss_thunder_warden` / `stone_guardian`) | `128x128` (or `256x256` profile) | `4px` (`8px` at 256) | `(64, 112)` (or `(128, 224)`) | `1.45` (`0.72` if 256px) |
| Combat VFX / Portal | `128x128` | `4px` | `(64, 64)` (`bbox_center`) or `(64, 112)` | `1.0` |

## 5. Animation & Direction Contract

- **Required Character/Enemy/Boss Animations:**
  - `idle`: 4 frames @ `6 fps`, `loop: true`
  - `walk`: 4 frames @ `8 fps`, `loop: true`
  - `attack`: 4 frames @ `12 fps`, `loop: false`
  - `hurt`: 2 frames @ `10 fps`, `loop: false`
  - `death`: 4 frames @ `8 fps`, `loop: false`
- **Frame Ordering:** Horizontal strip (`columns = frame_count`, `rows = 1`, `padding = 0`), left-to-right chronological order (`frame_000` → `frame_00N`).
- **Directions & Mirroring:**
  - Canonical rendered directions: `down` (`0°`), `right` (`90°`), `up` (`180°`).
  - `left` is derived at runtime via horizontal mirroring (`flip_uv` in profile, `AnimatedSprite2D.flip_h = true` in Godot). Characters must keep asymmetric details clean when mirrored.

## 6. Y-Sorting & Depth Alignment

- Parent `YSort` node in `scenes/main.tscn` sorts all obstacles, player, enemies, boss, and portal by their `Node2D.position.y` (ground contact point).
- Therefore, every sprite's feet/ground-contact point **must** sit at the pivot (`y = 112` on `128x128`) so `offset = (0, -48)` places the feet exactly at `(0, 0)` local origin.

## 7. Metadata, Versioning & Approval Status

- **Atlas Metadata:** Generated by `gameforge-kit` `atlas_packer.py` as `<task_id>.atlas.json` alongside `<task_id>.png` and `<character_id>_sprite_frames.tres`.
- **Asset Metadata Contract:** Follows `tools/gameforge-kit/schemas/asset_metadata.schema.json` (`schema_version: "1.0.0"`, `validation_status` in `["PENDING", "PASS", "REVIEW_REQUIRED", "APPROVED", "FAILED", "NOT_RUN"]`).
- **Approval Rule:** Batches with `REVIEW_REQUIRED` or `FAILED` must not be promoted to approved/production without human review. Existing `assets/generated/sprites/` remain valid for backward compatibility until replaced by approved batches.
